## A — Recents and suggestions

**What the user gets.** The empty palette leads with what they did last and
what matters now; the example chips move below as the fallback.

**Recents**

- New `src/utils/globalSearch/recents.js`: pure add / dedupe / cap / clear over
  a `{ queries: [{ text, at }], picks: [{ kind, id, label, at }] }` document.
  Picks store record identity only; labels are re-read from the live index on
  render so a renamed team or traded player never shows stale text, and a pick
  whose record is gone is dropped.
- Persist on this device only, in the existing `persist.js` IndexedDB store
  (new key, not tied to the app-version bust — recents must survive an upgrade).
  Never sent to the server. All reads/writes in
  try/catch; failure means no recents, never a broken palette.
- A query is recorded on Enter or result activation, not on every keystroke.

**Suggestions** (all from memory; never fetch)

- Your starters this week (connected league, from SleeperContext rosters).
- This week's games, live ones first (static schedule plus kickoff vs now).
- Your fantasy matchup when a week is in progress.
- Hidden entirely, not shown empty, when a source is unavailable.

**Files:** `recents.js` (new), `persist.js`, `useGlobalSearch.js`,
`GlobalSearchPalette.jsx`, `GlobalSearchGuide.jsx` (becomes the fallback
section), new `GlobalSearchHome.jsx`.

**Tests:** unit for `recents.js` (dedupe, cap, stale-pick drop, corrupt
storage); e2e: search → reopen → recent shown → Clear empties it.

## B1 — Inline compare card

The parser already emits `operator: 'compare'` with both sides; nothing consumes
it.

- New resolver `answers/compare.js`: two players, or two NFL teams, or two
  fantasy teams. Mixed kinds return null (row results still show).
- Players: season fantasy points and PPG through `scoringEngine.js`, positional
  rank (computed before any filter), trade value via `productionAdjustedValue`
  with null propagation (missing renders unavailable, never `0`), next opponent.
- Teams: the `teamStats.js` season model side by side; fantasy teams via
  `getFantasyRosterSeasonSummary`.
- Never fetches. A cold stats cache gives an identity-only card (name, team,
  position, bye) rather than nothing.
- Ambiguous sides ("josh allen vs kupp") pick the top-ranked record and show a
  one-tap swap to the other reading.
- The card's actions open each side's own page until B2 exists.

**Tests:** fixture-table cases in `globalSearchIntent.test.mjs`; resolver unit
tests incl. null propagation and the ambiguous-name case.

## C — Live score and game-status answers

Queries: `live score seahawks`, `seahawks score`, `who's playing now`,
`my live matchup`, `is jsn playing`.

**Availability gate (decision 2)**

- Live answers are on only when the host reports live data enabled — the same
  `getLiveStatus` / `getLiveConfigStatus().enabled` gate (BALLDONTLIE key,
  allowed league, cookie secret) and live session that Fantasy Live already
  uses. Read the gate the app already holds; do not add a second check.
- Gate off (self-hosted with no key, unreachable provider, league not allowed):
  no live resolver runs, no live request is made, and the live vocabulary still
  surfaces the Scores and Matchups destination rows. This is the keyless path
  CLAUDE.md requires — the feature is hidden, not shown as unavailable.

**Data, gate on**

| Need | Source |
| --- | --- |
| NFL game score and status | Live data already in memory (Scores, Fantasy Live, `useMatchupLiveFeed`); otherwise the app's own `/api/live` via `liveDataSource.js` |
| Fantasy live matchup | Fantasy Live's in-memory matchup state; otherwise `/api/live` plus Sleeper matchups the app already loaded |
| Player game status | Live box score from the same sources |

- **Memory first.** If a fresh live snapshot is already held, answer from it
  with no request.
- Otherwise one request to the app's own server: issued only once the parser has
  a live intent, after the input settles, deduped and cached ~30 s, aborted on
  query change, 4 s timeout. The browser never calls a third-party host.
- New `src/utils/globalSearch/live/liveSource.js` owns the gate, memory lookup
  and request; resolvers stay pure over what it returns. Copy never names a
  provider.
- **Degrade, never fail silently.** Offline, timeout, or error renders the
  navigation row (Scores game page or Matchups) with a short reason line.
- Live answers tick only while the palette is open and the card is visible; no
  background polling.

**Vocabulary:** live intent words (`live`, `score`, `now`, `playing`) added with
collision checks per the doc; `playing` must not break `cardinals playing`
schedule reads — the fixture table pins this.

**Tests:** resolver units over recorded snapshots (pre, live, final, postponed);
e2e with network stubbed for gate on, gate off (no live card, no `/api/live` request, destination rows still present), and offline.

## D — Actions on results

- The active row shows up to three secondary actions after the label; `Tab` /
  `→` moves into them, `Enter` runs one, `Esc` / `←` returns to the row. On
  touch, the expanded detail shows the same actions as 44px buttons.

| Kind | Actions |
| --- | --- |
| Player | Trade for (existing `onTradePlayer` path; partner preset from fantasy ownership), Add to draft board (`addPlayerToBoard`), Open owner's roster |
| NFL team | Schedule, Standings, Stats |
| Game | Scores page / matchup, depending on kickoff (existing `routeForGameResult`) |
| Fantasy team | Roster, Matchup, Head-to-head (from E2) |

- Actions hide, never disable, when unavailable (no league → no Trade for).
- All routes go through `appRoutes.js` builders and `detachSearchSheetEntry`.
- Keeps the motion rule: no animation, `mousemove` selection unchanged.
- Compare is added as an action once B2 exists.

**Tests:** unit for the action list per kind and availability; e2e keyboard path
into an action and back.

## E2 — League history and activity

Queries: `champions`, `2023 champion`, `me vs dana` / `head to head dana`,
`trades with dana`, `jsn trades`, `recent transactions`.

- Resolvers read only what is already cached:
  `getLeagueHistorySnapshot`'s `cachedFetch` entries and `buildLeagueHistoryModel`
  / `buildActivitySeasonGroups`. A cold cache degrades to the League history /
  activity destination row.
- Small in-memory records (one per past season and per manager) are added to the
  league slice in `buildLeagueRecords`; nothing goes into the static artifact.
- Only present with a connected league; manager names resolve through the
  existing fantasy-team records (team name, display name, username).
- Trades involving a player reuse the Trade history data and open Trade history
  filtered to that player if that filter exists; otherwise the unfiltered view.

**Tests:** resolver units over a two-season fixture (champion, H2H record,
player trades); intent fixtures for the new phrases.
